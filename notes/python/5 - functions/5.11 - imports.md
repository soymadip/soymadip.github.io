# Imports and Modules

Python's modular system allows you to organize code into separate files (modules) and directories (packages). This keeps your scripts clean and reusable.

## Common Import Patterns

### 1. Simple Import
Imports the entire module. You must use the module name to access its contents.

```python
import module
module.method()
```

### 2. Localized Import
Imports a specific object or function directly into your current namespace.

```python
from module import method
method()
```

### 3. Aliased Import
Renames the imported object to avoid naming conflicts or to shorten it.

```python
from module import brew as brr
brr()
```

## Packages and Submodules

A directory containing Python files is a **Package**. You can import from sub-directories using dot notation.

```python
# module/
#    recipies/
#        flavours.py

from recipies.flavours import ginger_chai
print(ginger_chai())
```

:::note __init__.py
Since Python 3.3, directories are automatically treated as packages even without an `__init__.py` file. However, you might still see them in older codebases for initialization logic.
:::

## Relative vs. Absolute Imports

Within a package, you can use relative imports to refer to sibling modules.

- `.` refers to the current directory.
- `..` refers to the parent directory.

```python
from .recipies import flavours
print(flavours.adrak_chai())
```

## Best Practices

- **Avoid Wildcard Imports:** `from module import *` is generally discouraged because it pollutes your namespace and makes it unclear where names come from.
- **Import Order:** Standard library first, then third-party packages, then local imports.
